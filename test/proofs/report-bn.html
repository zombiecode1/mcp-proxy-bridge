কিন্তু সীমাবদ্ধতা আছে: backend নিজে নতুন conversation_id generate করছে না। client-কে পাঠাতে হবে। আর full history load/replay করার dedicated endpoint এখনও নেই।

৪) Session buffer আসলে কী?

DiskRAGService-এ একটি sessionBuffer আছে, কিন্তু সেটা:

  • in-memory only
  • per-conversation isolated নয়
  • server restart হলে হারিয়ে যায়
  • legacy agent interactions-এর জন্য small buffer মাত্র
Meaning: individual session memory বর্তমানে production-grade session store নয়।

  • SSOT content-এর উপর keyword/section based search
  • workspace watcher দিয়ে SSOT auto-refresh
গুরুত্বপূর্ণ gap: ./embedding/-এ model artifact আছে, কিন্তু codebase-এ এখনো chunking + embeddings generation + vector-store ingestion pipeline wired করা নেই।

৬) “Auto index” করতে হলে কী লাগবে

বর্তমান অবস্থায় search option manual/SSOT-based। RAG-এর জন্য true auto index চাইলে দরকার হবে:

  • file chunker
  • embedding generator
  • persistent store (Qdrant, SQLite FTS, বা অন্য vector DB)
  • re-index trigger (file watcher / manual rescan / commit hook)
  • retrieval API, যাতে agent নির্দিষ্ট conversation/session context থেকে relevant chunks তুলতে পারে
Practical recommendation: SSOT + SQLite কে source of truth রাখুন, আর vector index কে retrieval acceleration layer হিসেবে যোগ করুন।

৮) PhpStorm, VS Code, আর VS Code-based editors-এর সাথে কিভাবে connect হবে?

আমাদের bridge-এর বড় সুবিধা হলো এটা http://localhost:5001/v1-এ OpenAI-compatible endpoint দিচ্ছে। তাই editor বা client যদি OpenAI-compatible provider config নিতে পারে, তাহলে সহজে connect করা সম্ভব।

  • LangChain ব্যবহার করলে base_url সেট করে এই bridge-এ connect করা যায়।
  • MCP ব্যবহার করলে editor/client tool discovery + resource access পায়, আর bridge-side tool endpoints expose করা যায়।
  • VS Code-based editors সাধারণত extension/client layer দিয়ে এই endpoint consume করতে পারে, যদি তারা OpenAI-compatible বা MCP-aware হয়।
  • PhpStorm / JetBrains-side connection editor-এর plugin/support layer-এর উপর নির্ভর করে; protocol-level support না থাকলে connector/plugin লাগবে।
বাস্তব উত্তর: editor connect হবে “নিজে নিজে” না; তাকে হয় OpenAI-compatible client, না হয় MCP client/plugin হিসেবে configure করতে হবে।

MCP হলো একটি open protocol, যা client এবং server-এর মধ্যে JSON-RPC style request/response দিয়ে tools, resources, prompts, ও context expose করার জন্য ব্যবহার হয়। Editor integrations-এর ক্ষেত্রে এটা useful।

  • tools discover করা যায়
  • resources expose করা যায়
  • editor/client ও agent side আলাদা রাখা যায়
Best fit: editor connectivity এবং standardized tool access-এর জন্য MCP শক্তিশালী choice।
